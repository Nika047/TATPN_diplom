===============================================================================
 ЧАСТЬ 2. НАСТРОЙКА НА КОМПЬЮТЕРЕ С GPU
===============================================================================

ТРЕБОВАНИЯ
  - видеокарта NVIDIA с актуальным драйвером;
  - Python 3.10 или новее;
  - git.

ШАГ 2.1. Склонировать репозиторий

    git clone https://github.com/Nika047/TATPN_diplom.git
    cd TATPN_diplom

ШАГ 2.2. Создать виртуальное окружение

  Windows:
    python -m venv .venv
    .venv\Scripts\activate

  Linux:
    python3 -m venv .venv
    source .venv/bin/activate

ШАГ 2.3. Установить PyTorch с поддержкой CUDA

  ВАЖНО: обычный "pip install torch" может поставить версию без CUDA,
  и тогда всё опять будет считаться на процессоре. Нужна сборка под CUDA.
  Актуальную команду взять на https://pytorch.org/get-started/locally/
  (выбрать свою ОС, пакетный менеджер pip и версию CUDA).

  Для видеокарт серии RTX 50 (архитектура Blackwell, например 5070 Ti)
  нужна сборка под CUDA 12.8 или новее. Сборки под CUDA 12.1 такие карты
  не поддерживают: torch.cuda.is_available() может вернуть True, а
  вычисления упадут с ошибкой "no kernel image is available". Для CUDA 12.8
  нужен достаточно свежий драйвер NVIDIA (серия 570 и новее).

    pip install torch --index-url https://download.pytorch.org/whl/cu128

  Если torch уже стоит с другой версией CUDA, сначала удалить:
    pip uninstall -y torch

ШАГ 2.4. Установить остальные зависимости

    pip install -r requirements.txt

ШАГ 2.5. ОБЯЗАТЕЛЬНО проверить, что GPU виден

    python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

  Должно напечатать True и название видеокарты, например:
    True NVIDIA GeForce RTX 5070 Ti

  Одной проверки is_available() мало: на неподдерживаемой архитектуре она
  проходит, а вычисления падают. Проверить реальную операцию на видеокарте:

    python -c "import torch; x = torch.randn(512, 512, device='cuda'); print((x @ x).sum().item(), torch.cuda.get_device_capability(0))"

  Должно напечатать число и пару вида (12, 0) без ошибок. Ошибка
  "no kernel image is available for execution on the device" означает,
  что сборка torch не поддерживает эту видеокарту - см. шаг 2.3.

  Если напечатало False - значит стоит сборка PyTorch без CUDA или проблема
  с драйвером. Запускать этапы в этом случае НЕ ИМЕЕТ СМЫСЛА: всё посчитается
  на процессоре в урезанном режиме, как раньше. Сначала переустановить torch
  по шагу 2.3.

  Дополнительная проверка: при запуске любого этапа первая строка вывода
  должна быть
    [config] CUDA доступна: <название карты>, <объём> ГБ VRAM. Используется GPU.
  Если вместо неё
    [config] CUDA недоступна, используется CPU.
  то GPU не подхватился.

-------------------------------------------------------------------------------
ЭТАП 0. Подготовка данных
-------------------------------------------------------------------------------
    python run_stage0.py

  Что делает: разбирает 150 CSV-логов, считает кинематические признаки,
  аугментирует реальные данные, генерирует синтетические боевые сценарии,
  сохраняет датасет.

  Создаёт:
    processed_data/all_trajectories.npz
    processed_data/normalizer.npz
    reports/stage0_data_report.html

  Что проверить в выводе:
    - строка "[Parser] Найдено 150 уникальных CSV-файлов" (без дубликатов);
    - итоговое количество траекторий по слоям (реальные / расширенные /

-------------------------------------------------------------------------------
ЭТАП 1. Пайплайн оценки и опорные бейзлайны (без обучения)
-------------------------------------------------------------------------------
    python run_stage1.py

  Обучаемых параметров нет. Этап доказывает, что тракт
  данные -> нарезка окон -> метрики корректен, и задаёт опорную планку.

  Смотреть: logs/stage1_baselines/summary.txt

  Что обязательно должно быть:
    [OK] window_contiguity - расстояние last_point -> future[0] мало
         (десятки метров). Если здесь километры - нарезка окон сломана,
         дальше идти нельзя;
    [OK] baseline_sane
    [OK] deterministic

  ЗАПИСАТЬ СЕБЕ ADE и FDE линейной экстраполяции. Это опорная планка, с
  которой сравниваются все нейросети на последующих этапах.

-------------------------------------------------------------------------------
ЭТАП 2. CNN baseline
-------------------------------------------------------------------------------
    python run_stage2.py

  Смотреть: logs/stage2_cnn/summary.txt
  Обязательные проверки: overfit_one_batch, learned.
  Цель этапа (не блокирующая): ADE лучше линейной экстраполяции.

  Главное: val ADE должен падать по эпохам. Если стоит на месте - модель
  не учится.

-------------------------------------------------------------------------------
ЭТАП 3. CNN + Mamba
-------------------------------------------------------------------------------
    python run_stage3.py

  Смотреть: logs/stage3_cnn_mamba/summary.txt
  Проверки: overfit_one_batch, learned.
  Цели: лучше линейной и лучше CNN Этапа 2.

  Здесь же записывается время эпохи и inference - на GPU должно быть
  в разы быстрее, чем на CPU (на CPU было 141-270 секунд на эпоху).

-------------------------------------------------------------------------------
ЭТАП 4. + Target Head (классификация цели)
-------------------------------------------------------------------------------
    python run_stage4.py

  Смотреть: logs/stage4_target/summary.txt
  Проверки: overfit_one_batch, traj_learned, target_learned,
            traj_not_degraded.

  Главные числа:
    - Acc@1 должен быть заметно выше случайного (случайно = 1/15 = 0.067);
    - таблица Acc@1 по доле наблюдения 20/40/60/80% должна РАСТИ -
      чем больше траектории видно, тем точнее определяется цель;
    - ADE не должен вырасти относительно Этапа 3.

  График: reports/stage4_accuracy_vs_observation.png

-------------------------------------------------------------------------------
ЭТАП 5. Полная модель TATPN
-------------------------------------------------------------------------------
    python run_stage5.py

  Cross-Attention с обучаемыми эмбеддингами целей + авторегрессионный
  GRU-декодер + оценка времени до цели (ETA). Это центральная модель диплома.

  Смотреть: logs/stage5_tatpn/summary.txt
  Проверки: overfit_one_batch, traj_competitive, target_learned, eta_learned.
  Цели: Acc@1 лучше Этапа 4; ADE лучше линейной экстраполяции.

  Главные числа: ADE, Acc@1, Acc@3, MAE_ETA (в секундах) и сравнение
  MAE_ETA с наивным предсказанием среднего.

  График: reports/stage5_accuracy_vs_observation.png

ЭТАП 6. Визуализация и демонстрация

===============================================================================
 ПРИЛОЖЕНИЕ. РАБОТА С GPU-КОМПЬЮТЕРОМ ЧЕРЕЗ SSH ПО RADMIN VPN (разные сети)
===============================================================================

Условия: GPU-компьютер (Windows 11) стоит дома, управлять им нужно с
рабочего компьютера (Windows 10). Это ДВЕ РАЗНЫЕ СЕТИ.

ГЛАВНОЕ ОГРАНИЧЕНИЕ
Адрес вида 192.168.x.x работает только внутри одной сети. С работы по нему
домашний компьютер не найти.

РЕШЕНИЕ: Radmin VPN
Бесплатная программа (только Windows), которая объединяет компьютеры в
виртуальную сеть. После этого они видят друг друга как в одной локальной
сети, а у каждого появляется адрес вида 26.x.x.x. Дальше работает обычный
SSH, только вместо 192.168.x.x используется этот адрес.
Сайт: https://www.radmin-vpn.com/

Названия пунктов меню в программе могут немного отличаться от приведённых
ниже - ориентируйтесь по смыслу.

МОЖНО ЛИ НАСТРОИТЬ ВЕЧЕРОМ, А ПОДКЛЮЧАТЬСЯ УТРОМ - ДА.
Всё, что требует физического доступа, делается вечером дома. Утром на работе
остаётся установить Radmin VPN на рабочий компьютер, войти в ту же сеть
и подключиться.

-------------------------------------------------------------------------------
ВЕЧЕРОМ, на домашнем компьютере (Windows 11), PowerShell от администратора
-------------------------------------------------------------------------------
1. Включить SSH-сервер:

    Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
    Set-Service -Name sshd -StartupType Automatic
    Start-Service sshd

2. Проверить, что SSH работает (подключение к самому себе):

    ssh $env:USERNAME@localhost

   Должно запросить пароль и войти. Выйти командой exit.

   ВАЖНО: нужен именно пароль учётной записи Windows. Если вход выполняется
   через Microsoft-аккаунт - пароль от этого аккаунта, а НЕ PIN-код. Если
   пароля у учётной записи нет вообще, SSH по паролю не пустит - сначала
   задайте пароль.

3. Установить Radmin VPN (https://www.radmin-vpn.com/) и создать сеть:
     - в программе: меню "Сеть" (Network) -> "Создать сеть" (Create network);
     - придумать название сети и пароль и ЗАПИСАТЬ их - утром на рабочем
       компьютере они понадобятся для входа;
     - записать адрес 26.x.x.x этого компьютера: он виден в списке
       компьютеров, обычно его можно скопировать правым кликом по
       компьютеру;
     - в настройках программы убедиться, что включён запуск вместе
       с Windows.

4. Проверить, что порт 22 открыт в брандмауэре для всех профилей сети.
   Адаптер Radmin VPN Windows может считать общедоступной сетью, и тогда
   правило, действующее только для частной сети, SSH не пропустит.

    Get-NetFirewallRule -Name *ssh* | Select-Object Name, Enabled, Direction, Profile

   Должно быть правило с Enabled = True, Direction = Inbound, Profile = Any.
   Если правила нет или профиль ограничен:

    New-NetFirewallRule -Name sshd-any -DisplayName "OpenSSH Server (any profile)" -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22 -Profile Any

5. Запретить засыпание компьютера, иначе утром он будет недоступен:

    powercfg /change standby-timeout-ac 0
    powercfg /change hibernate-timeout-ac 0

   Компьютер должен остаться включённым и подключённым к интернету.
   Выключать и переводить в сон нельзя. Экран можно гасить.

6. Проверить SSH по адресу виртуальной сети (подставить свой 26.x.x.x):

    ssh $env:USERNAME@26.x.x.x

   Это проверяет, что sshd принимает подключения на адресе Radmin VPN.
   Полную проверку из другой сети сделать вечером нельзя - она будет утром
   (см. ниже, команда Test-NetConnection).

7. Склонировать проект и подготовить окружение (можно сделать сразу же):

    git clone https://github.com/Nika047/TATPN_diplom.git
    cd TATPN_diplom
    python -m venv .venv
    .venv\Scripts\activate
    pip install torch --index-url https://download.pytorch.org/whl/cu128
    pip install -r requirements.txt
    python -c "import torch; print(torch.cuda.is_available())"

   Должно напечатать True. Если False - сборка PyTorch без CUDA или
   проблема с драйвером (см. Часть 2, шаги 2.3 и 2.5).

-------------------------------------------------------------------------------
УТРОМ, на рабочем компьютере (Windows 10)
-------------------------------------------------------------------------------
1. Установить Radmin VPN (для установки обычно нужны права администратора,
   так как программа ставит сетевой драйвер) и войти в сеть:
     - меню "Сеть" -> "Присоединиться к существующей сети"
       (Join an existing network);
     - ввести название сети и пароль, записанные вечером.
   В списке должен появиться домашний компьютер в состоянии "в сети".
   Если его нет - см. раздел "Если не подключается" ниже.

2. Проверить, что порт 22 доступен (подставить адрес домашнего ПК):

    Test-NetConnection 26.x.x.x -Port 22

   В выводе должно быть TcpTestSucceeded : True.

3. Подключиться (подставить имя пользователя домашнего ПК и его адрес):

    ssh имя_пользователя@26.x.x.x

   При первом подключении спросит про отпечаток ключа - ответить yes, затем
   ввести пароль учётной записи домашнего ПК.

   ВАЖНО: после входа по SSH на Windows открывается командная строка cmd,
   а не PowerShell. Команды этого приложения (Get-Content, Get-Process и
   т.п.) работают только в PowerShell, поэтому сразу после входа набрать:

    powershell

4. Запускать этапы по порядку, как в Части 3. Короткие этапы (0-2) можно
   запускать обычным образом: python run_stage1.py

   Долгие этапы (3-5) нужно запускать так, чтобы они не зависели от
   SSH-сессии: при её закрытии или обрыве обычный запуск и даже
   Start-Process могут завершиться вместе с ней. Надёжный способ - запуск
   через WMI, процесс принадлежит системе, а не сессии. Находясь в папке
   проекта в PowerShell:

    $P = (Get-Location).Path
    Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{ CommandLine = "cmd /c `"cd /d $P && .venv\Scripts\python.exe run_stage5.py > stage5.out 2>&1`"" }

   В ответе должно быть ReturnValue = 0 и номер процесса (ProcessId).
   Один раз проверьте на коротком этапе, что запущенный так процесс
   переживает выход из SSH (закрыть сессию, зайти заново, посмотреть
   Get-Process python).

   Следить за ходом (журнал пишется в logs\run_logs\, берём самый свежий):

    Get-ChildItem logs\run_logs | Sort-Object LastWriteTime -Descending | Select-Object -First 1 -ExpandProperty FullName

   и затем:

    Get-Content ПОЛНЫЙ_ПУТЬ_К_ЖУРНАЛУ -Tail 20 -Wait

   Ежедневный порядок действий - в файле md/DAILY_ROUTINE.md.

-------------------------------------------------------------------------------
ЕСЛИ НЕ ПОДКЛЮЧАЕТСЯ
-------------------------------------------------------------------------------
  - домашний ПК ушёл в сон или перезагрузился (например, из-за обновления
    Windows). После перезагрузки может потребоваться войти в учётную запись
    на самом домашнем ПК, чтобы Radmin VPN снова поднялся;
  - Radmin VPN не запущен на одном из компьютеров;
  - в списке Radmin VPN домашний ПК не "в сети" - проверить первые два пункта;
  - домашний ПК в сети, но Test-NetConnection даёт False - не пропускает
    брандмауэр (вечерний шаг 4) или остановлена служба sshd:
    Get-Service sshd   (при необходимости: Start-Service sshd);
  - ssh отвергает пароль - вспомнить про PIN-код и пароль Microsoft-аккаунта
    (вечерний шаг 2);
  - рабочая сеть или политика компьютера блокирует VPN или установку
    программ - тогда этот способ не сработает.

ЗАПАСНОЙ ВАРИАНТ
Если Radmin VPN не заработает, вместо него подойдёт Tailscale
(https://tailscale.com/download, бесплатен для личного использования):
ставится на оба компьютера, вход под одним аккаунтом, адрес вида 100.x.y.z.
Команды SSH те же, меняется только адрес.
