Все результаты, полученные до сих пор, считались на CPU в сильно урезанном

1. Исправлено дублирование исходных логов.
   Раньше run_stage0.py читал две папки: flight_logs_source/ внутри проекта

   и в тестовую выборку - то есть утечку данных.

     - data_processing/parser.py - дедупликация CSV по имени файла;
     - run_stage0.py - читается только flight_logs_source/;
     - flight_logs_source/ дополнен до полного набора (150 CSV).

2. Репозиторий стал самодостаточным.
   Исходные логи лежат в git (150 CSV, ~22 МБ), а датасет пересоздаётся
   идентично на любой машине, потому что генератор и аугментор засеяны
   фиксированным RANDOM_SEED = 42. Большие файлы (processed_data/ с npz на
   302 МБ, artifacts/, logs/) в git не хранятся и переносить их НЕ НУЖНО.

3. Удалены устаревшие чекпоинты прежней архитектуры (освобождено ~1.28 ГБ).

4. История репозитория начата заново и опубликована на GitHub (ветка main).
   Прежняя история содержала сгенерированные HTML-отчёты общим объёмом
   около 900 МБ. GitHub не принимает файлы больше 100 МБ, поэтому пуш
   обрывался, а история не сохранялась. Старые отчёты удалены.
   Размер репозитория теперь около 23 МБ (240 файлов).

===============================================================================
 ЧАСТЬ 2. НАСТРОЙКА НА КОМПЬЮТЕРЕ С GPU
===============================================================================

ТРЕБОВАНИЯ
  - видеокарта NVIDIA с актуальным драйвером;
  - Python 3.10 или новее;
  - git.

ШАГ 2.1. Склонировать репозиторий

    git clone https://github.com/Nika047/TATPN_diplom.git
    cd TATPN_diplom

ШАГ 2.2. Создать виртуальное окружение

  Windows:
    python -m venv .venv
    .venv\Scripts\activate

  Linux:
    python3 -m venv .venv
    source .venv/bin/activate

ШАГ 2.3. Установить PyTorch с поддержкой CUDA

  ВАЖНО: обычный "pip install torch" может поставить версию без CUDA,
  и тогда всё опять будет считаться на процессоре. Нужна сборка под CUDA.
  Актуальную команду взять на https://pytorch.org/get-started/locally/
  (выбрать свою ОС, пакетный менеджер pip и версию CUDA).

  Пример для CUDA 12.1:
    pip install torch --index-url https://download.pytorch.org/whl/cu121

ШАГ 2.4. Установить остальные зависимости

    pip install -r requirements.txt

ШАГ 2.5. ОБЯЗАТЕЛЬНО проверить, что GPU виден

    python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

  Должно напечатать True и название видеокарты, например:
    True NVIDIA GeForce RTX 3060

  Если напечатало False - значит стоит сборка PyTorch без CUDA или проблема
  с драйвером. Запускать этапы в этом случае НЕ ИМЕЕТ СМЫСЛА: всё посчитается
  на процессоре в урезанном режиме, как раньше. Сначала переустановить torch
  по шагу 2.3.

  Дополнительная проверка: при запуске любого этапа первая строка вывода
  должна быть
    [config] CUDA доступна: <название карты>, <объём> ГБ VRAM. Используется GPU.
  Если вместо неё
    [config] CUDA недоступна, используется CPU.
  то GPU не подхватился.

 ЧАСТЬ 3. ЗАПУСК ПО ЭТАПАМ (по порядку, не все сразу)

Запускать строго по одному этапу и после каждого смотреть сводку. Так видно,

-------------------------------------------------------------------------------
ЭТАП 0. Подготовка данных
-------------------------------------------------------------------------------
    python run_stage0.py

  Что делает: разбирает 150 CSV-логов, считает кинематические признаки,
  аугментирует реальные данные, генерирует синтетические боевые сценарии,
  сохраняет датасет.

  Создаёт:
    processed_data/all_trajectories.npz
    processed_data/normalizer.npz
    reports/stage0_data_report.html

  Что проверить в выводе:
    - строка "[Parser] Найдено 150 уникальных CSV-файлов" (без дубликатов);
    - итоговое количество траекторий по слоям (реальные / расширенные /
      синтетические). Реальных станет меньше, чем было раньше (было 214 с
      дубликатами) - это правильно;
    - распределение по 15 целям должно быть примерно равномерным.

  ВАЖНО: фактические количества траекторий из этого вывода нужно будет
  перенести в README.md, md/STAGE0_REPORT.md и md/IMPLEMENTATION_PLAN.md -
  там пока стоят старые числа (214 реальных, 3707 всего).

-------------------------------------------------------------------------------
ЭТАП 1. Пайплайн оценки и опорные бейзлайны (без обучения)
-------------------------------------------------------------------------------
    python run_stage1.py

  Обучаемых параметров нет. Этап доказывает, что тракт
  данные -> нарезка окон -> метрики корректен, и задаёт опорную планку.

  Смотреть: logs/stage1_baselines/summary.txt

  Что обязательно должно быть:
    [OK] window_contiguity - расстояние last_point -> future[0] мало
         (десятки метров). Если здесь километры - нарезка окон сломана,
         дальше идти нельзя;
    [OK] baseline_sane
    [OK] deterministic

  ЗАПИСАТЬ СЕБЕ ADE и FDE линейной экстраполяции. Это опорная планка, с
  которой сравниваются все нейросети на последующих этапах.

-------------------------------------------------------------------------------
ЭТАП 2. CNN baseline
-------------------------------------------------------------------------------
    python run_stage2.py

  Смотреть: logs/stage2_cnn/summary.txt
  Обязательные проверки: overfit_one_batch, learned.
  Цель этапа (не блокирующая): ADE лучше линейной экстраполяции.

  Главное: val ADE должен падать по эпохам. Если стоит на месте - модель
  не учится.

-------------------------------------------------------------------------------
ЭТАП 3. CNN + Mamba
-------------------------------------------------------------------------------
    python run_stage3.py

  Смотреть: logs/stage3_cnn_mamba/summary.txt
  Проверки: overfit_one_batch, learned.
  Цели: лучше линейной и лучше CNN Этапа 2.

  Здесь же записывается время эпохи и inference - на GPU должно быть
  в разы быстрее, чем на CPU (на CPU было 141-270 секунд на эпоху).

-------------------------------------------------------------------------------
ЭТАП 4. + Target Head (классификация цели)
-------------------------------------------------------------------------------
    python run_stage4.py

  Смотреть: logs/stage4_target/summary.txt
  Проверки: overfit_one_batch, traj_learned, target_learned,
            traj_not_degraded.

  Главные числа:
    - Acc@1 должен быть заметно выше случайного (случайно = 1/15 = 0.067);
    - таблица Acc@1 по доле наблюдения 20/40/60/80% должна РАСТИ -
      чем больше траектории видно, тем точнее определяется цель;
    - ADE не должен вырасти относительно Этапа 3.

  График: reports/stage4_accuracy_vs_observation.png

-------------------------------------------------------------------------------
ЭТАП 5. Полная модель TATPN
-------------------------------------------------------------------------------
    python run_stage5.py

  Cross-Attention с обучаемыми эмбеддингами целей + авторегрессионный
  GRU-декодер + оценка времени до цели (ETA). Это центральная модель диплома.

  Смотреть: logs/stage5_tatpn/summary.txt
  Проверки: overfit_one_batch, traj_competitive, target_learned, eta_learned.
  Цели: Acc@1 лучше Этапа 4; ADE лучше линейной экстраполяции.

  Главные числа: ADE, Acc@1, Acc@3, MAE_ETA (в секундах) и сравнение
  MAE_ETA с наивным предсказанием среднего.

  График: reports/stage5_accuracy_vs_observation.png

-------------------------------------------------------------------------------
ЭТАП 6. Визуализация и демонстрация
-------------------------------------------------------------------------------
    python run_stage6.py

  Обучения нет, работает быстро. Загружает обученную модель Этапа 5.

  Создаёт в reports/stage6/:
    report.html       - сводный отчёт: таблица метрик по всем этапам
                        и графики;
    example_1..6.html - интерактивные карты: наблюдаемая и предсказанная
                        траектории, 15 целей с вероятностями, ETA.

  Открыть report.html в браузере. Карты используют тайлы OpenStreetMap,
  поэтому для их отображения нужен интернет.

  Демонстрация на отдельной траектории:
    python demo.py --test-index 5
    python demo.py --csv "flight_logs_source/<имя файла>.csv"
  Результат: reports/stage6/demo.html плюс оценка угрозы в консоли.

 ЧАСТЬ 5. ЕСЛИ ЧТО-ТО НЕ ТАК
===============================================================================

"CUDA недоступна, используется CPU"
  Стоит сборка PyTorch без CUDA. Переустановить по шагу 2.3.

"Не найден processed_data/all_trajectories.npz"
  Не выполнен Этап 0. Запустить run_stage0.py.

"Не найден чекпоинт artifacts/stage5/best.pt"
  Не выполнен Этап 5. Этапы 6 и demo.py требуют обученной модели Этапа 5.

Нехватка видеопамяти (CUDA out of memory)
  Уменьшить BATCH в начале файла run_stage3.py / run_stage4.py /
  run_stage5.py (в ветке для cuda), например с 64 до 32 или 16.

Проверка window_contiguity на Этапе 1 провалилась (километры вместо метров)
  Сломана нарезка окон. Дальше идти нельзя - разбираться с data/windowing.py.

Обучение идёт, но val ADE не падает
  Модель не учится. Смотреть overfit-one-batch: если он тоже не сходится -
  проблема в данных или скорости обучения, а не в архитектуре.

Карты в reports/stage6/ открываются пустыми
  Нет интернета - не загружаются тайлы OpenStreetMap и библиотека Leaflet.

===============================================================================
 ПРИЛОЖЕНИЕ. РАБОТА С GPU-КОМПЬЮТЕРОМ ЧЕРЕЗ SSH (разные сети)
===============================================================================

Условия: GPU-компьютер (Windows 11) стоит дома, управлять им нужно с
рабочего компьютера (Windows 10). Это ДВЕ РАЗНЫЕ СЕТИ.

ГЛАВНОЕ ОГРАНИЧЕНИЕ
Адрес вида 192.168.x.x работает только внутри одной сети. С работы по нему
домашний компьютер не найти. Нужен один из вариантов:

  Вариант 1 (рекомендуется): Tailscale.
    Бесплатен для личного использования, не требует настройки роутера
    и открытия портов в интернет. Устанавливается на оба компьютера,
    вход под одной учётной записью. После этого компьютеры видят друг друга
    как в одной сети, у каждого появляется адрес вида 100.x.y.z и имя.
    Сайт: https://tailscale.com/download

  Вариант 2: проброс порта 22 на домашнем роутере.
    Не рекомендуется: SSH оказывается открыт всему интернету. Если всё же
    выбран этот путь - только вход по ключам, пароль отключить.

МОЖНО ЛИ НАСТРОИТЬ ВЕЧЕРОМ, А ПОДКЛЮЧАТЬСЯ УТРОМ - ДА.
Всё, что требует физического доступа, делается вечером дома. Утром на работе
остаётся установить Tailscale на рабочий компьютер и подключиться.

-------------------------------------------------------------------------------
ВЕЧЕРОМ, на домашнем компьютере (Windows 11), PowerShell от администратора
-------------------------------------------------------------------------------
1. Включить SSH-сервер:

    Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
    Set-Service -Name sshd -StartupType Automatic
    Start-Service sshd

2. Проверить, что SSH работает (подключение к самому себе):

    ssh $env:USERNAME@localhost

   Должно запросить пароль и войти. Выйти командой exit.

   ВАЖНО: нужен именно пароль учётной записи Windows. Если вход выполняется
   через Microsoft-аккаунт - пароль от этого аккаунта, а НЕ PIN-код. Если
   пароля у учётной записи нет вообще, SSH по паролю не пустит - сначала
   задайте пароль.

3. Установить Tailscale (https://tailscale.com/download), войти в аккаунт.
   Записать имя компьютера и его адрес 100.x.y.z (виден в приложении
   Tailscale или командой tailscale ip).

4. Запретить засыпание компьютера, иначе утром он будет недоступен:

    powercfg /change standby-timeout-ac 0
    powercfg /change hibernate-timeout-ac 0

   Компьютер должен остаться включённым и подключённым к интернету.
   Выключать и переводить в сон нельзя. Экран можно гасить.

5. По возможности проверить с другой сети: подключить телефон как точку
   доступа к рабочему компьютеру или любому устройству с Tailscale
   и попробовать ssh на домашний компьютер.

6. Склонировать проект и подготовить окружение (можно сделать сразу же):

    git clone https://github.com/Nika047/TATPN_diplom.git
    cd TATPN_diplom
    python -m venv .venv
    .venv\Scripts\activate
    pip install torch --index-url https://download.pytorch.org/whl/cu121
    pip install -r requirements.txt
    python -c "import torch; print(torch.cuda.is_available())"

   Должно напечатать True. Если False - сборка PyTorch без CUDA или
   проблема с драйвером (см. Часть 2, шаги 2.3 и 2.5).

-------------------------------------------------------------------------------
УТРОМ, на рабочем компьютере (Windows 10)
-------------------------------------------------------------------------------
1. Установить Tailscale и войти ПОД ТЕМ ЖЕ аккаунтом, что и дома.
   Для установки обычно нужны права администратора. Если на рабочем
   компьютере их нет или сетевая политика блокирует VPN-программы - этот
   вариант не сработает, понадобится другой способ.

2. Подключиться (подставить имя пользователя и имя/адрес домашнего ПК):

    ssh имя_пользователя@имя-компьютера
    ssh имя_пользователя@100.x.y.z

3. Запускать этапы по порядку, как в Части 3. Обучение длится долго, а
   при обрыве SSH-сессии процесс умирает. Чтобы он пережил разрыв:

    Start-Process -FilePath ".\.venv\Scripts\python.exe" -ArgumentList "run_stage5.py" -RedirectStandardOutput "stage5.out" -RedirectStandardError "stage5.err" -WindowStyle Hidden

   Следить за ходом:

    Get-Content stage5.out -Wait -Tail 20

   Этапы 0-2 короткие, их можно запускать обычным образом.

ЕСЛИ НЕ ПОДКЛЮЧАЕТСЯ
  - домашний ПК ушёл в сон или перезагрузился (обновление Windows);
  - Tailscale не запущен на одном из компьютеров;
  - служба sshd остановлена: Get-Service sshd на домашнем ПК;
  - рабочая сеть блокирует VPN.
