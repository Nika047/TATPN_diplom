# Система прогнозирования положения воздушного объекта

Магистерская диссертация - нейросетевая система прогнозирования траектории
воздушного объекта (БПЛА) при помощи алгоритмов экстраполяции. Целевая
архитектура - гибрид Multi-Scale CNN + Mamba (selective state space model)
с прогнозом цели полёта и времени подлёта.

## Что делает система (итоговая цель)

По наблюдаемому участку траектории совместно прогнозировать:

1. Будущую траекторию (координаты x, y, z).
2. Вероятную цель полёта из базы объектов критической инфраструктуры
   (классификация).
3. Оставшееся время до цели (ETA, секунды).

## Методология: пошаговое усложнение

Проект строится инкрементально - один компонент за этап. Каждый этап это
минимальное, полностью рабочее приложение с собственным запускаемым
скриптом и таблицей метрик. Между этапами метрики сравниваются, поэтому
всегда видно, какой именно компонент дал улучшение или поломку.

> Первая (монолитная) версия собирала весь TATPN сразу и оказалась сломана
> без возможности локализовать причину. Разбор - в `md/DIAGNOSIS_STAGE1.md`,
> пересмотренный план - в `md/IMPLEMENTATION_PLAN.md`. Прежний код перенесён
> в папку `не надо/` как справочник и целевая архитектура позднего этапа.

### Дорожная карта этапов

| Этап | Содержание | Статус |
|------|-----------|--------|
| 0 | Данные и инфраструктура (парсинг, кинематика, база целей, генерация) | готово |
| 1 | Пайплайн оценки + не-нейросетевые бейзлайны (без обучения) | готово |
| 2 | CNN baseline (только координаты) | план |
| 3 | + Mamba энкодер (только координаты) | план |
| 4 | + Target Head (классификация цели) | план |
| 5 | Полный TATPN (Cross-Attention + авторегрессия + ETA) | план |
| 6 | Визуализация и демонстрация | план |
| 7 | Сравнение с другими архитектурами (бонус) | план |

## Быстрый старт

### Установка

```bash
pip install -r requirements.txt
```

### Этап 0 - подготовка данных

```bash
python run_stage0.py
```

Парсит реальные CSV-логи, применяет аугментацию, генерирует синтетические
сценарии и сохраняет `processed_data/all_trajectories.npz` (3607 траекторий)
и `processed_data/normalizer.npz`. Отчёт: `reports/stage0_data_report.html`.

### Этап 1 - пайплайн оценки и бейзлайны

```bash
python run_stage1.py
```

Обучения нет. Скрипт формирует окна прогноза новым корректным способом,
считает два бейзлайна на тесте (константа и линейная экстраполяция),
проверяет масштаб координат и контигуальность окон (защита от бага 70 км),
сохраняет:
- `logs/stage1_baselines/history.json` - метрики (машиночитаемо),
- `logs/stage1_baselines/summary.txt` - краткая сводка,
- `logs/run_logs/stage1_baselines_<timestamp>.log` - полный лог запуска.

Ожидаемо: расстояние `last_point -> future[0]` мало (порядка шага dt),
все проверки PASS, зафиксированы опорные ADE/FDE линейной экстраполяции.

## Запуск на машине с GPU

Репозиторий самодостаточен: реальные логи (`flight_logs_source/`, 150 CSV)
лежат в git, а датасет пересоздаётся идентично на любой машине - генератор и
аугментор засеяны `RANDOM_SEED`. Большие файлы (`processed_data/`, `artifacts/`,
`logs/`) в git не хранятся и переносить их не нужно.

```bash
git clone https://github.com/Nika047/TATPN_diplom.git
cd TATPN_diplom
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Затем этапы по порядку (сверяя `logs/<этап>/summary.txt` после каждого):

```bash
python run_stage0.py
python run_stage1.py
python run_stage2.py
python run_stage3.py
python run_stage4.py
python run_stage5.py
python run_stage6.py
```

Весь цикл (этапы 0-6, все эпохи, с замером времени) одной командой:

```bash
python run_all.py
```

Итог - в `logs/run_all/summary.txt`. Прикидку времени без обучения даёт
`python benchmark_gpu.py`.

**Важно про сравнимость метрик.** При наличии CUDA `config.py` автоматически
включает полный профиль, а `run_stage3/4/5` - свои GPU-настройки:

| Параметр | CPU | GPU |
|---|---|---|
| PRED_HORIZON | 30 | 50 |
| MAX_SEQ_LEN | 192 | 512 |
| Окно этапов 3-5 | 48 | 192 |
| Mamba | 2 x 128 | 4 x 256 |
| Batch (этапы 3-5) | 8 | подбирается по VRAM (до 128) |
| Эпохи, максимум (этапы 3-5) | 12 | 100 (ранняя остановка) |

ADE на горизонте 50 шагов несравним с ADE на 30, поэтому на GPU нужно
перезапустить **все** этапы (0-6), чтобы итоговая таблица была на одном
конфиге.

## Метрики качества

- Траектория: ADE, FDE, RMSE, MAE (метры), плюс ADE@10 / ADE@20 / ADE@50.
- Классификация цели (с Этапа 4): Acc@1, Acc@3, Brier.
- ETA (с Этапа 5): MAE_ETA, RMSE_ETA (секунды).

Все траекторные метрики учитывают маску валидности (паддинг не штрафуется).

## Датасет

Трёхслойная стратегия формирования обучающей выборки:

| Слой | Состав | Количество |
|------|--------|------------|
| 1 | Реальные логи полётов БПЛА | 107 |
| 2 | Аугментированные (scale 200, stitch 150, warp 150) | 500 |
| 3 | Синтетические боевые сценарии | 3000 |
| Итого | | 3607 |

Реальных траекторий 107, а не 214: прежде каждый лог читался из двух копий
папки и учитывался дважды (см. `md/DIAGNOSIS_STAGE1.md`).

Разбиение на выборки (train 2524 / val 541 / test 542) делается **по исходным
полётам**: реальные полёты делятся 70/15/15, а расширенные траектории каждой
выборки порождаются только из реальных полётов этой же выборки, поэтому
производные от одного полёта не попадают в разные выборки. Метки выборок
хранятся в датасете (`data_processing/splits.py`).

Синтетические сценарии: direct (60%), evasion (20%), loitering (10%),
deceptive (10%). Подробности - в `md/DATA_STRATEGY.md` и `md/DATASET_ANALYSIS.md`.
