# Поэтапный план реализации (пересмотренный)

Тема: система прогнозирования положения воздушного объекта при помощи
алгоритмов экстраполяции на основе нейронной сети.

## Главный принцип

Каждый этап - это минимальное, полностью рабочее приложение. Сложность
растёт строго по одному компоненту за этап. Между этапами метрики
сравниваются, чтобы всегда было видно, какой именно компонент и на каком
шаге дал улучшение или поломку. Если метрика деградировала - виноват
ровно тот компонент, который добавлен на этом этапе.

> Почему план пересмотрен. В первой версии "Этап 1" сразу содержал весь
> TATPN (Multi-Scale CNN + Mamba + Adaptive Pooling + Cross-Attention +
> авторегрессионный GRU-декодер + ETA + multi-task loss). Он оказался
> сломан (val ADE ~ 70 000 м, Acc@1 ~ 0.19), и из-за того, что всё было
> собрано разом, локализовать причину было почти невозможно. Разбор см. в
> `DIAGNOSIS_STAGE1.md`. Прежний код перенесён в папку `не надо/` и будет
> переиспользован как целевая архитектура на позднем этапе.

## Правила, общие для всех этапов

### Инкрементальность
- Один этап = плюс один компонент к предыдущему.
- Реализация каждого этапа - в НОВЫХ файлах (старый код лежит в `не надо/`
  как справочник, не импортируется).
- Каждый этап завершается запускаемым `run_stageN.py`, который печатает
  таблицу метрик и сохраняет отчёт.

### Диагностическое логирование (обязательно на каждом этапе)
Логи нужны, чтобы автоматически ловить "где всё пошло не так":

1. **Sanity масштаба.** На каждой оценке логировать min/mean/max по
   предсказанным и по истинным координатам, а также расстояние
   `last_point -> future[0]`. Если это расстояние - десятки км, значит
   окно observed/future рассинхронизировано (именно это сломало прежний
   Этап 1).
2. **Не-нейросетевой бейзлайн всегда в таблице.** ADE/FDE линейной
   экстраполяции по последней скорости. Если обучаемая модель хуже
   бейзлайна - что-то сломано, а не "модель слабая".
3. **Overfit на малом наборе.** Перед полным обучением прогнать 600 шагов на
   8 образцах без dropout: loss обязан упасть не менее чем в 5 раз. Быстрый
   детектор оторванного графа, кривых таргетов или плохого lr (минуты вместо
   часов). Условия подобраны калибровкой: прежний вариант (весь батч из 32-96
   образцов, dropout включён, порог в 10 раз) давал ложный FAIL на исправных
   моделях (`training/diagnostics.py`).
4. **Оценка без teacher forcing.** Метрики на val/test считаются в
   eval-режиме без подсказок. Train-метрики помечаются как "с TF" и не
   сравниваются напрямую с val (в прежней версии из-за этого train ADE
   выглядел в 15 раз лучше val).
5. **Единый формат логов.** На каждый запуск:
   - `logs/<stage>/history.json` - метрики по эпохам (машиночитаемо),
   - `logs/<stage>/summary.txt` - краткая сводка (человекочитаемо: финальные
     метрики, сравнение с предыдущим этапом и с бейзлайном),
   - `logs/run_logs/<stage>_<timestamp>.log` - полный лог консоли.
6. **Фиксация seed** (42) для numpy/torch, чтобы прогоны воспроизводились.

### Метрики (единые определения для всех этапов)
- Траектория: ADE, FDE, RMSE, MAE (в метрах), плюс ADE@10/@20/@50.
- Все траекторные метрики учитывают `future_mask` (паддинг не штрафуется).
- Классификация цели (с этапа 4): Acc@1, Acc@3, Brier.
- ETA (с этапа 5): MAE_ETA, RMSE_ETA (в секундах).

## Этап 0. Данные и инфраструктура - ГОТОВО

> Результат: чистый датасет + генератор + аугментация + база целей.

Реализовано в `run_stage0.py` и `data_processing/`. Итог:
`processed_data/all_trajectories.npz` - 3607 траекторий (реальные 107,
scale 200, stitch 150, warp 150, синтетические direct 1800 / evasion 600 /
loitering 300 / deceptive 300), сбалансированы по 15 целям, без NaN,
формат `(N, 4)` = (x, y, z, dt) в ENU-метрах; `normalizer.npz` - z-score
по 15 признакам. Отчёт: `reports/stage0_data_report.html`.

### Что оставляем как есть
- Парсер CSV -> ENU, фильтрация GPS, ресемплирование (`parser.py`).
- Кинематика: 15 признаков, каналы 0-2 = x,y,z; 3 = dt; 4-6 = vx,vy,vz;
  7 = |v|; 8-10 = ax,ay,az; 11 = heading; 12 = climb_angle; 13 = curvature;
  14 = heading_rate (`kinematics.py`).
- База целей (`target_database.py`, `targets.json`).
- Генерация и аугментация (`generator.py`, `augmentor.py`).

### Что переделываем при реализации следующих этапов
Формирование обучающих пар (нарезка observed/future) в
`data_processing/dataloader.py` содержит критический баг: наблюдаемое окно
берётся с НАЧАЛА траектории (`observed[:seq_len]`), а `split_idx` и future
считаются по полной длине. Так как 94% траекторий длиннее `MAX_SEQ_LEN`,
точка инициализации декодера и начало future оказываются в десятках км друг
от друга. Новый даталоадер (в новых файлах) должен:
- брать ХВОСТ наблюдения перед точкой разреза: `observed[-MAX_SEQ_LEN:]`;
- гарантировать, что `future[0]` пространственно смежен с последней
  наблюдаемой точкой (расстояние ~ один шаг, не десятки км);
- логировать эту величину (sanity-проверка №1).
Сами данные `all_trajectories.npz` переиспользуются без перегенерации.

## Этап 2. CNN baseline (только координаты)

> Результат: простая свёрточная сеть предсказывает будущие точки.
> Первая обучаемая модель. Baseline для сравнения.

### 2.1 Модель `models/cnn_baseline.py` (новый)
- Вход: `(B, T, F=15)` кинематических признаков (нормализованные).
- 3 x Conv1d(F->64->128->256) + BatchNorm + ReLU.
- Masked Global Average Pool -> FC -> `(B, H, 3)`.
- Прогноз: `pred_k = last_point + delta_k`. Сеть предсказывает будущее САМА,
  без встроенной физической экстраполяции - всё движение извлекается из
  наблюдаемых признаков. БЕЗ velocity-prior: prior маскировал бы обучение и
  вклад архитектуры (проверено - см. первый прогон Этапа 2).
- Последний слой инициализируется нулём: старт delta=0 (= "стоять на месте"),
  затем модель учится смещению. Кривая обучения интерпретируема.
- Loss: Huber (smooth L1) только по траектории, с маской, масштаб координат
  100 м (здоровые градиенты при ошибках в сотни метров).

### 2.2 Обучение `run_stage2.py`
- AdamW, lr из config; overfit на малом наборе перед полным прогоном (training/diagnostics.py).
- Обучение с ранней остановкой по val ADE (CNN лёгкая, эпоха ~15 с на CPU,
  поэтому не ограничиваемся CPU-профилем в 5 эпох).
- Сохранение лучшей модели по val ADE.

### Проверка этапа 2
Обязательные (пайплайн и обучение исправны):
```
[ ] overfit на малом наборе (8 образцов, без dropout): loss падает не менее чем в 5 раз
[ ] модель реально обучилась: лучший val ADE ниже стартового на >= 20%
```
Цель этапа (научный результат, не блокирует переход):
```
[ ] ADE(CNN) < ADE(линейная экстраполяция) из этапа 1
```
Если простая CNN не обгоняет классическую линейную экстраполяцию - это
честный результат, мотивирующий переход к временному моделированию (Mamba,
Этап 3). Плюс сохраняются 10 примеров "прогноз vs истина".

## Этап 3. CNN + Mamba энкодер (только координаты)

> Результат: заменяем/дополняем свёрточный фронт Mamba-энкодером.
> По-прежнему только координаты - чтобы изолировать вклад Mamba.

### 3.1 Модель `models/cnn_mamba.py` (новый)
- Multi-Scale CNN (ядра 3/7/15, без MaxPool) -> проекция в d_model.
- Mamba Encoder: селективный SSM на чистом PyTorch (реализация есть в
  `не надо/models/mamba.py` - переносим и проверяем отдельным smoke-тестом).
- Adaptive Context Pooling (attention по последним K состояниям).
- FC-голова -> `(B, H, 3)` дельты. Loss: Huber с маской.

### 3.2 Обучение `run_stage3.py`
- Замерить время эпохи и inference (в history.json и summary).
- CPU-настройки (по замерам): время эпохи определяется длиной окна L
  (scan-цикл), а не размером батча. Поэтому на CPU берём укороченное окно
  L=64 и батч 32 (эпоха ~2.8 мин против ~18 мин при L=192). Mamba: 2 слоя,
  d_model=128, d_state=8 (CPU-профиль config).
- Честность сравнения: якорь - линейная экстраполяция - НЕ зависит от L
  (считается по точке разреза), поэтому проверка "обгон линейной" одинакова
  на всех этапах. CNN Этапа 2 (обучен при L=192) идёт справочной строкой с
  явной пометкой про разное окно.

### Проверка этапа 3
Обязательные:
```
[ ] overfit на малом наборе (8 образцов, без dropout): loss падает не менее чем в 5 раз
[ ] модель реально обучилась: лучший val ADE ниже стартового на >= 20%
[ ] замерены время эпохи и inference
```
Цели этапа (научный результат, не блокируют):
```
[ ] ADE(CNN+Mamba) < ADE(линейная экстраполяция)
[ ] ADE(CNN+Mamba) < ADE(CNN baseline, этап 2)
```

## Этап 4. + Target Head (классификация цели)

> Результат: модель предсказывает не только точки, но и вероятную цель
> из базы объектов. Появляется multi-task.

Задача классификации: выбрать 1 из K=15 целей. Помимо контекста траектории
используем геометрические подсказки к каждой цели: расстояние, угол между
курсом и направлением на цель, отклонение от прямой к цели.

### 4.1 Реализация
- `features/geometry.py` (новый): `compute_geometric_features(traj, targets)`
  -> `(B, K, G)`.
- `models/target_head_mlp.py` (новый): `concat(context, geo) -> scores ->
  softmax`.
- Multi-task loss: `L = alpha*L_traj + beta*L_target`
  (масштабирование координат в loss, чтобы CE не терялся - см. COORD_SCALE).

### 4.2 Метрики цели
- Acc@1, Acc@3, Brier; график accuracy vs доля наблюдения (20/40/60/80%).

### Проверка этапа 4

## Этап 5. Полный TATPN (Cross-Attention + авторегрессия + ETA)

> Результат: целевая архитектура. Собирается из проверенных этапов 2-4 +
> адаптированный код из `не надо/`.

### Cross-Attention target head
Каждая цель получает эмбеддинг = TypeEmbedding(тип) + MLP(координаты).
Q = контекст траектории, K/V = эмбеддинги целей. attention даёт логиты
целей; target-aware вектор идёт в декодер и ETA-голову. Позволяет
обобщать по типу цели (похожие цели получают похожий отклик).

### Авторегрессионный декодер
GRU step-by-step: `pos_{t+1} = pos_t + v_last*dt + correction`, коррекция
ограничена tanh. Прогноз по одной точке, каждая следующая зависит от
предыдущей. teacher forcing по расписанию (0.5 -> 0.0 по эпохам), оценка
всегда без TF.

### 5.1 Реализация
- `models/tatpn.py` (новый, адаптированный): TargetEncoder,
  CrossAttentionTargetHead, AutoregressiveDecoder, ETA-head.
- Полный loss: `L = alpha*L_traj + beta*L_target + gamma*L_eta`.
- Warm-up весов (первые эпохи меньше beta), затем полный.

### Проверка этапа 5
```
[ ] overfit на малом наборе (8 образцов, без dropout): loss падает не менее чем в 5 раз
[ ] Acc@1 > этапа 4 (Cross-Attention > простой MLP) либо паритет
[ ] ADE/FDE не хуже этапа 3
[ ] ETA: MAE_ETA в секундах записана
[ ] distance(last_point -> future[0]) мал (баг 70 км не воспроизводится)
```
