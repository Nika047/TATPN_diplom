# Разбор поломки первой версии Этапа 1

Документ фиксирует, что и почему сломалось в первой (монолитной) версии
Этапа 1, где сразу был собран весь TATPN. Служит и техническим разбором,
и материалом для раздела диплома "анализ ошибок / отладка".

## Симптомы (из логов обучения)

Источник: `logs/tatpn_stage1/history.json`, `reports/stage1_train_report.json`
(CPU-профиль: B=4, L=192, PRED_HORIZON=30, 5 эпох, 642k параметров).

| Метрика | Значение | Что ожидалось |
|---------|----------|---------------|
| val ADE ~ FDE | ~70 000 м, не убывает по эпохам | десятки-сотни м |
| train ADE | ~4700 м, при FDE ~130 м | ADE <= FDE |
| train ADE@10 > ADE@20 > ADE | перевёрнутый порядок | ADE@k растёт с k |
| Acc@1 | ~0.19 (при 15 целях случайно 0.067) | заметно выше |
| Brier | ~0.9 | ближе к 0 |
| MAE_ETA | ~1100 с | - |
| время эпохи (CPU) | ~40 мин | - |

Флаг: val ADE постоянен (~70 км) при любом числе эпох. Значит проблема не
в обучении, а в постановке (данные/нарезка), которую обучение исправить не
может.

## Корневая причина: рассинхрон окон observed и future

Файл `data_processing/dataloader.py`, метод `__getitem__`.

1. Точка разреза и future считаются по ПОЛНОЙ длине траектории:
   ```python
   split_idx = ... int(n_points * observe_ratio) ...      # напр. 1328
   future = xyz[split_idx:split_idx + PRED_HORIZON]        # точки 1328..1358
   ```
2. Наблюдаемое окно обрезается с НАЧАЛА до MAX_SEQ_LEN:
   ```python
   observed_padded[:seq_len] = observed[:seq_len]          # только точки 0..191
   ```
3. Декодер инициализируется последней ВАЛИДНОЙ точкой окна (индекс 191),
   а предсказывать должен точки с 1328.

Между точкой 191 и точкой 1328 траектория проходит ~1130 шагов. Из данных:
**94% траекторий длиннее MAX_SEQ_LEN (медиана 2657 точек)**, поэтому баг
срабатывает почти всегда. Разрыв в пространстве - десятки км, отсюда
ADE ~ 70 км.

### Почему train выглядел "нормально"
Teacher forcing (0.5 -> 0.0) на train подставлял в `prev` истинную точку,
поэтому каждый шаг стартовал рядом с целью и накопления ошибки не было -
train ADE занижен, а порядок ADE@k перевёрнут (артефакт TF, не баг метрик).
На val TF выключен, разрыв окон проявляется полностью.

## Почему было трудно локализовать
В одном "Этапе 1" одновременно работали: Multi-Scale CNN, Mamba,
Adaptive Pooling, Cross-Attention, авторегрессионный декодер, ETA-голова и
трёхкомпонентный loss. Любой из них мог давать 70 км. Поиск причины требовал
разбирать всё сразу, а один прогон на CPU занимал ~3.3 часа.

## Выводы, заложенные в новый план
1. Нарезка: брать ХВОСТ наблюдения (`observed[-MAX_SEQ_LEN:]`), future -
   сразу за ним; логировать `distance(last_point -> future[0])`.
2. Инкрементальность: по одному компоненту за этап (см. IMPLEMENTATION_PLAN).
3. Диагностика до обучения: sanity-масштаб, не-нейросетевой бейзлайн,
   overfit-one-batch, оценка без teacher forcing.
