# Архитектура системы прогнозирования цели вражеского БПЛА

## Постановка задачи (уточнённая)

### Боевой контекст
Система предназначена для **оценки угрозы со стороны вражеского БПЛА**: по наблюдаемой траектории определить, какой объект критической инфраструктуры является вероятной целью атаки (город, НПЗ, военная база, скопление людей и т.д.).

### Ключевые ограничения
- **Доступны только внешние наблюдения**: координаты (x, y, z) и время (t) — данные с РЛС/оптических средств. Никакой телеметрии дрона (скорость, крен, тяга, батарея) у нас нет.
- **Нужно предсказать не «20 следующих точек», а конечную цель** — конкретный объект на карте.
- **В перспективе**: учёт метеорологических условий (ветер, видимость) и рельефа местности (горы, реки, застройка) как факторов, влияющих на маршрут.

### Что на выходе
1. **Вероятностное распределение по целям**: P(цель_i | траектория) для каждого объекта из базы
2. **Экстраполированная траектория до наиболее вероятной цели**
3. **Оценка времени подлёта** к каждой вероятной цели
4. **Визуализация на карте**: маршрут + цели + вероятности

---

## Критический анализ текущего решения

### Что хорошо
- CNN + Transformer гибрид — разумная базовая идея
- Зонная классификация 3×3×3 — прообраз целевой классификации

### Что не подходит для боевой задачи
1. **Предсказание «20 точек»** — бесполезно без привязки к реальным объектам на местности
2. **Зоны 3×3×3 в абстрактном пространстве** — не связаны с реальной географией
3. **Использует 60+ параметров телеметрии** — у противника эти данные недоступны
4. **Нет карты целей** — модель не знает, ЧТО находится в пространстве
5. **Нет учёта рельефа и метео** — БПЛА не летит по прямой через горы и против штормового ветра
6. **Mean pooling** теряет динамику последних наблюдений (самых важных)

## Предлагаемая архитектура: Target-Aware Trajectory Prediction Network (TATPN)

### Общая идея: три уровня задачи

```
Уровень 1: ЭКСТРАПОЛЯЦИЯ ТРАЕКТОРИИ
    Вход: наблюдаемая траектория (x, y, z, t) 
    Выход: предсказанные будущие точки

Уровень 2: ПРЕДСКАЗАНИЕ ЦЕЛИ
    Вход: траектория + карта целей + (опционально) рельеф + метео
    Выход: P(цель_i) — вероятность для каждого объекта инфраструктуры

Уровень 3: ВИЗУАЛИЗАЦИЯ УГРОЗЫ
    Вход: результаты уровней 1-2
    Выход: карта с маршрутом, целями, вероятностями, временем подлёта
```

### Полная схема архитектуры

## Детали каждого компонента

### 1. Кинематический Вычислитель (KinematicFeatureExtractor)

Это чисто вычислительный слой (не обучаемый), работающий с сырыми координатами:

```python
# Входные данные от РЛС: только (x, y, z, t)
# Из них вычисляем:

dt = t[i+1] - t[i]                           # временной шаг
vx = (x[i+1] - x[i]) / dt                    # скорость по X
vy = (y[i+1] - y[i]) / dt                    # скорость по Y  
vz = (z[i+1] - z[i]) / dt                    # скорость по Z
speed = sqrt(vx² + vy² + vz²)                # полная скорость
ax = (vx[i+1] - vx[i]) / dt                  # ускорение по X
ay = (vy[i+1] - vy[i]) / dt                  # ускорение по Y
az = (vz[i+1] - vz[i]) / dt                  # ускорение по Z
heading = atan2(vy, vx)                       # курс (горизонтальный)
climb_angle = atan2(vz, sqrt(vx²+vy²))       # угол набора/снижения
curvature = |v × a| / |v|³                   # кривизна траектории
heading_rate = d(heading)/dt                  # скорость изменения курса
```

Итого **~12 признаков** из 4 исходных. Всё это можно получить от РЛС — никакой телеметрии дрона не нужно.

### 2. Multi-Scale CNN

Три параллельные ветки без пулинга:
- **k=3**: захватывает мгновенные манёвры (резкий поворот, уклонение)
- **k=7**: средние паттерны (фаза разворота, набор высоты)
- **k=15**: глобальное направление движения

Важно: **без MaxPool**, чтобы Mamba получил полную временную последовательность.

### 3. Mamba Encoder

Почему Mamba, а не Transformer:
- **Линейная сложность O(T)** — критично для реального времени в боевых условиях
- **Селективный механизм** — модель сама учится, какие точки траектории важны (начало? последний манёвр? момент смены курса?)
- **Trajectory Mamba (CVPR 2025)** — доказано превосходство на задачах предсказания траекторий

### 4a. Trajectory Head (экстраполяция траектории)

Авторегрессионный GRU-декодер:
```python
h = context_vector
prev_pos = last_observed_position
predictions = []

for step in range(horizon):
    inp = concat([prev_pos, h])
    h = GRU_cell(inp, h)
    delta = Linear(h)           # предсказываем СМЕЩЕНИЕ, не абс. позицию
    next_pos = prev_pos + delta
    predictions.append(next_pos)
    prev_pos = next_pos
```

Предсказание **дельт** (смещений) вместо абсолютных координат — это стабильнее и лучше обобщается.

### 4b. Target Prediction Head (КЛЮЧЕВОЙ НОВЫЙ КОМПОНЕНТ)

Это главная новизна работы. Механизм Cross-Attention между траекторией и целями:

```python
# Контекст траектории (из Mamba Encoder)
traj_context = adaptive_pool(mamba_output)  # (B, D)

# Эмбеддинги целей из базы
# Каждая цель: (lat, lon, alt, type_embedding, importance_score)
target_embeddings = TargetEncoder(target_database)  # (K, D)

# Cross-Attention: "куда смотрит траектория?"
Q = Linear(traj_context)                  # (B, 1, D) — запрос от траектории
K = Linear(target_embeddings)             # (K, D) — ключи целей
V = Linear(target_embeddings)             # (K, D) — значения целей

# Вычисляем "совместимость" траектории с каждой целью
attention_scores = Q @ K.T / sqrt(D)      # (B, K)

# Дополнительные признаки для каждой пары (траектория, цель):
# - расстояние от текущей позиции до цели
# - угол между текущим курсом и направлением на цель
# - отклонение от прямой линии к цели
geometric_features = compute_geometric(current_pos, heading, targets)  # (B, K, G)

# Объединяем attention с геометрическими признаками
combined = concat([attention_scores, geometric_features], dim=-1)
target_probs = softmax(MLP(combined))     # (B, K) — вероятность каждой цели

# Оценка времени подлёта (регрессия)
eta = ReLU(Linear(combined))              # (B, K) — время в секундах
```

### 5. Карта Целей (TargetDatabase)

Внешний модуль — не нейросеть, а **структурированная база данных**:

```python
class TargetDatabase:
    targets = [
        {"id": 1, "name": "НПЗ Рязань",      "lat": 54.6, "lon": 39.7, "type": "refinery",      "importance": 0.9},
        {"id": 2, "name": "г. Москва",         "lat": 55.7, "lon": 37.6, "type": "city",          "importance": 1.0},
        {"id": 3, "name": "аэродром Энгельс", "lat": 51.5, "lon": 46.2, "type": "airbase",       "importance": 0.95},
        {"id": 4, "name": "ТЭЦ-5",            "lat": 55.8, "lon": 37.5, "type": "power_plant",   "importance": 0.7},
        {"id": 5, "name": "склад ГСМ",         "lat": 54.2, "lon": 38.1, "type": "fuel_depot",    "importance": 0.8},
        # ... произвольное количество объектов
    ]
    
    type_embedding = Embedding(num_types=10, dim=32)
    # Типы: city, refinery, power_plant, airbase, fuel_depot, 
    #        bridge, dam, port, military_base, event_venue
```

Каждая цель кодируется:
- Координаты (lat, lon, alt) → нормализованные
- Тип объекта → learned embedding (32-мерный вектор)
- Важность (приоритет) → скаляр
- Опционально: площадь объекта, уязвимость, наличие ПВО

## Учёт рельефа и метеоусловий (перспектива)

### Рельеф (Digital Elevation Model)

Идея: БПЛА не может лететь сквозь горы. Рельеф влияет на вероятные маршруты.

```
Подход 1 (простой): Карта высот как дополнительный слой
    - Загрузить DEM (например, SRTM с разрешением 30м)
    - Для каждой предсказанной точки проверить: высота БПЛА > высота рельефа + запас
    - Штрафовать траектории, проходящие через рельеф

Подход 2 (продвинутый): Рельеф как входной признак
    - Для каждой наблюдаемой точки (x,y,z) добавить признак:
      terrain_clearance = z_бпла - z_рельеф(x, y)
    - Модель учится, что БПЛА держит определённый зазор над рельефом
```

### Метеорологические условия

```
Подход 1 (простой): Ветер как глобальный контекст
    - Вектор ветра (wx, wy) на высоте полёта
    - Подаётся как дополнительный вход в Mamba Encoder
    - БПЛА смещается по ветру → модель учитывает это

Подход 2 (продвинутый): Пространственно-временное поле ветра
    - Ветер может быть разным в разных точках пространства
    - Используется как дополнительный канал в CNN
    - Или как дополнительный контекст в Cross-Attention
```

### Как это встраивается в архитектуру

```
Кинематический вычислитель:
    (x, y, z, t) → (12 кинематических признаков)
                  + terrain_clearance(x, y, z)      ← рельеф
                  + wind_x(x, y, z, t)              ← метео
                  + wind_y(x, y, z, t)              ← метео
                  = 15 признаков

Target Prediction Head:
    geometric_features включает:
    + terrain_difficulty(current_pos → target)       ← «сложность» маршрута по рельефу
    + headwind_component(current_pos → target, wind) ← встречный/попутный ветер до цели
```

## Loss Function (функция потерь)

Многозадачная потеря:

```python
L_total = α * L_trajectory + β * L_target + γ * L_eta

# L_trajectory: ошибка экстраполяции (MSE/Huber по координатам)
L_trajectory = HuberLoss(pred_points, true_points)

# L_target: классификация цели (Cross-Entropy)
L_target = CrossEntropyLoss(pred_target_probs, true_target_id)

# L_eta: ошибка оценки времени подлёта (MSE)
L_eta = MSELoss(pred_eta, true_eta)

# Веса: α=1.0, β=2.0 (главная задача — цель!), γ=0.5
```

## Как тренировать: создание обучающих данных

### Проблема
В текущем датасете нет меток «целей». Логи дронов — это просто полёты.

### Решение: имитация боевых сценариев

```
1. Берём реальную траекторию из датасета
2. Размещаем N «целей» на карте (случайно или по реальным координатам)
3. Конечная точка траектории = ближайшая цель (или цель, к которой 
   дрон летит по направлению)
4. Метка = ID этой цели
5. Обрезаем траекторию на X% — это «наблюдаемая часть»
6. Задача модели: по наблюдаемой части предсказать цель

Варианты создания обучающих сценариев:
  a) Случайные цели + реальные траектории
  b) Реальные координаты объектов инфраструктуры (OpenStreetMap)
  c) Синтетические прямолинейные + криволинейные маршруты к целям
  d) Аугментация: зашумление, обрезка, масштабирование реальных траекторий
```

## Элемент научной новизны

1. **Target-Aware архитектура для прогнозирования цели БПЛА** — в отличие от TNT (CoRL 2020), который работает с автомобильными траекториями и road graph, наша модель работает с 3D-пространством без дорожной сети
2. **CNN-Mamba encoder для 3D-траекторий БПЛА** — первое применение SSM к задаче оценки угрозы от БПЛА (в литературе Mamba применяется к 2D автомобильным/пешеходным траекториям)
3. **Cross-Attention между траекторией и базой целей** — механизм «внимания к целям», позволяющий динамически оценивать совместимость текущей траектории с каждым объектом
4. **Двухголовая архитектура** (trajectory + target) с общим encoder — multi-task learning, где экстраполяция траектории помогает предсказанию цели и наоборот
5. **Перспектива учёта рельефа и метео** — расширяемость архитектуры (даже если не реализовано полностью — это направление для будущих работ)

## План реализации (этапы)

### Этап 0: Подготовка данных
- Перевод GPS в метрическую систему (ENU)
- Кинематический вычислитель (скорости, ускорения из позиций)
- Генерация «сценариев с целями» из существующих траекторий
- Нормализация

### Этап 1: Baseline — улучшенный CNN+Transformer
- Починить mean pooling → adaptive context pooling
- Добавить кинематические признаки
- Добавить Target Head с простым расстоянием до целей
- Это baseline для сравнения

### Этап 2: CNN-Mamba Encoder
- Заменить Transformer на Mamba
- Сравнить по ADE/FDE/Target Accuracy

### Этап 3: Полная архитектура TATPN
- Cross-Attention с целями
- Авторегрессионный декодер
- Multi-task loss

### Этап 4: Визуализация и демонстрация
- Отображение на реальной карте (folium / plotly)
- Цели с вероятностями и временем подлёта
- HTML-отчёт / интерактивная карта

### Этап 5 (бонус): Рельеф и метео
- Подключить DEM (SRTM)
- Простая модель ветра
- Показать влияние на точность
