# Отчёт по Этапу 0: Данные и инфраструктура

## 1. Анализ исходных данных

### 1.1 Состав датасета

Исходные данные представляют собой CSV-логи телеметрии учебных полётов беспилотных летательных аппаратов (БПЛА), предоставленные компанией «Ленинец». Датасет включает записи полётов БПЛА 10 различных моделей, классифицируемых по типу конструкции:

- **Самолётный тип**: Dolphin (51 файл), Z84 (8), Mini Talon (2)
- **Коптерный тип**: Chimera7 (21), F450 (16)
- **VTOL**: T1 VTOL (8)
- **Симуляторы (самолёт)**: GoDiscover (27), Sim (8)
- **Прочие**: S1100 (6), Chernika (3)

Всего: **150 CSV-файлов**.

### 1.2 Формат данных

Данные записаны в формате OpenTX телеметрии. Для задачи прогнозирования используются следующие поля:

| Поле | Описание | Использование |
|------|----------|---------------|
| GPS | Широта и долгота (строка) | Координаты X, Y |
| Alt(m) | Высота в метрах | Координата Z |
| Time | Временная метка HH:MM:SS.fff | Временной ряд dt |

### 1.3 Выявленные проблемы

В ходе анализа были выявлены следующие проблемы:

1. **GPS-аномалии**: приблизительно 13% файлов (16 из 150) содержат некорректные GPS-данные — скачки координат на тысячи километров, нереалистичные высоты (от -33293 м до +30512 м).

2. **Короткие траектории**: медиана длительности полёта составляет ~10.7 минут, медиана удаления от точки старта — 1762 м. Для боевого сценария (десятки-сотни километров) эти данные недостаточны.

3. **Отсутствие целенаправленного движения**: учебные полёты представляют собой кружение и манёвры, а не направленное движение к конкретной цели.

4. **Переменная частота записи**: интервал между точками составляет ~2 секунды (не фиксированный).

### 1.4 Зона полётов

Анализ GPS-координат показал, что все реальные полёты проводились в районе Гатчина/Коммунар (~59.045° N, 29.093° E), приблизительно в 45 км к югу от Санкт-Петербурга.

## 2. Разработка системы предобработки данных

### 2.1 Преобразование координат (ENU)

Для работы с данными в метрической системе реализовано преобразование из геодезических координат WGS84 (широта, долгота, высота) в локальную метрическую систему ENU (East-North-Up):

- **E (East)** — смещение на восток от опорной точки, метры
- **N (North)** — смещение на север, метры
- **U (Up)** — высота, метры

Опорная точка выбрана в центре зоны полётов: 59.045° N, 29.093° E. Преобразование использует упрощённую формулу, пригодную для расстояний до 500 км:

```
E = (lon - lon0) * 111320 * cos(lat0)
N = (lat - lat0) * 111320
U = alt - alt0
```

Модуль: `data_processing/parser.py`, функции `geodetic_to_enu()`, `enu_to_geodetic()`.

### 2.2 Фильтрация GPS-аномалий

Реализован многоступенчатый фильтр GPS-аномалий:

1. Удаление точек с нулевыми координатами (lat=0 или lon=0)
2. Удаление точек с нереалистичными высотами (< -100 м или > 10000 м)
3. Удаление точек со скачком координат более 500 м за один временной шаг (с учётом пропорциональности к длительности интервала)

Модуль: `data_processing/parser.py`, функция `filter_gps_anomalies()`.

### 2.3 Ресемплирование

Для получения равномерного временного ряда выполняется линейная интерполяция координат на фиксированный шаг dt = 1.0 с (параметр `RESAMPLE_DT` в `config.py`).

Модуль: `data_processing/parser.py`, функция `resample_trajectory()`.

## 3. Вычисление кинематических признаков

Из 4 базовых координат (x, y, z, dt) вычисляются 11 дополнительных кинематических признаков, характеризующих динамику движения БПЛА:

| № | Признак | Формула | Описание |
|---|---------|---------|----------|
| 1-3 | vx, vy, vz | Центральные разности | Компоненты вектора скорости (м/с) |
| 4 | \|v\| | sqrt(vx²+vy²+vz²) | Модуль скорости (м/с) |
| 5-7 | ax, ay, az | Разности скоростей | Компоненты ускорения (м/с²) |
| 8 | heading | atan2(vx, vy) | Курс в горизонтальной плоскости (рад) |
| 9 | climb_angle | atan2(vz, \|v_h\|) | Угол набора высоты (рад) |
| 10 | curvature | \|vx·ay - vy·ax\| / \|v\|³ | Кривизна траектории (1/м) |
| 11 | heading_rate | d(heading)/dt | Угловая скорость поворота (рад/с) |

Итого: **15 входных признаков** для нейронной сети.

Для подавления высокочастотного шума применяется сглаживание скользящим средним с окном 5 точек. При вычислении производных используются центральные разности для внутренних точек и односторонние разности для граничных.

Модуль: `data_processing/kinematics.py`, функция `compute_kinematics()`.

## 5. Стратегия формирования обучающей выборки

### 5.1 Трёхслойная архитектура данных

Для компенсации ограничений реальных данных (короткие траектории, отсутствие целенаправленного движения) разработана трёхслойная стратегия формирования датасета:

**Слой 1 — Реальные данные (107 траекторий).** Обработанные CSV-логи реальных полётов. Обеспечивают модели реалистичную кинематику: GPS-шум, паттерны ускорения и поворотов реальных БПЛА.

**Слой 2 — Расширенные реальные данные (~500 траекторий).** Получены из реальных данных тремя методами:
- *Scale & Translate* — масштабирование координат в 10-50 раз с переносом к целевому объекту
- *Stitch* — сшивка 3-5 реальных траекторий в один длинный маршрут через кубические сплайны
- *Warp to Target* — деформация реальной траектории (поворот, растяжение) с добавлением участка подхода к цели

**Слой 3 — Синтетические боевые сценарии (~3000 траекторий).** Программно сгенерированные маршруты четырёх типов:
- *Прямой маршрут (60%)* — движение от точки старта к цели с GPS-шумом и ветровым сносом
- *Маршрут с уклонением (20%)* — 1-3 промежуточных waypoint, соединённых кубическими сплайнами
- *Барражирование (10%)* — полёт к промежуточной точке, кружение (1-3 оборота), затем заход на цель
- *Ложный маршрут (10%)* — начало движения к одной цели с последующей сменой курса на другую

### 5.2 Параметры генерации

Синтетические траектории генерируются с учётом реалистичных параметров полёта:

| Параметр | Диапазон | Описание |
|----------|----------|----------|
| Скорость | 10-60 м/с (36-216 км/ч) | Зависит от типа БПЛА |
| Высота | 30-2000 м | Три диапазона (низкий, средний, высотный) |
| Расстояние | 10-500 км | Три диапазона (ближний, средний, дальний) |
| GPS-шум | sigma = 10 м | Типичный для гражданского GPS |
| Ветровой снос | 50-500 м амплитуда | Низкочастотная синусоидальная модуляция |
| Профиль высоты | Набор/крейсер/снижение | 10%/70%/20% от длины маршрута |

### 5.3 Формирование обучающих пар

Для каждой траектории формируются обучающие пары с варьированием процента наблюдения:

- **Вход**: первые X% траектории (X выбирается случайно из диапазона 20-80%)
- **Метки**: идентификатор цели, будущие точки (до 50), время до конечной точки (ETA)
- **Padding**: дополнение до фиксированной длины (MAX_SEQ_LEN = 512) с маской

Варьирование X% позволяет модели учиться предсказывать цель на разных этапах полёта — чем раньше модель определяет вероятную цель, тем ценнее она для системы ПВО.

### 5.4 Итоговый размер датасета

| Компонент | Траекторий | Обучающих пар (при 4 вариациях X%) |
|-----------|------------|-------------------------------------|
| Слой 1 (реальные) | 107 | ~430 |
| Слой 2 (расширенные) | 490 | ~1960 |
| Слой 3 (синтетические) | 3000 | ~12000 |
| **Итого** | **3597** | **~14400** |

CSV, без дубликатов). Колонка "обучающих пар" - оценка при 4 вариациях X%.

Разбиение: 70% train / 15% validation / 15% test.

## 6. Нормализация данных

Реализован класс `FeatureNormalizer` с поддержкой двух методов нормализации:

- **Z-score (стандартная)**: x_norm = (x - mean) / std
- **Min-Max**: x_norm = (x - min) / (max - min)

По умолчанию используется Z-score нормализация. Статистики (mean, std) вычисляются **только на обучающей выборке** и применяются к валидационной и тестовой выборкам для предотвращения утечки данных. Статистики сохраняются в файл `normalizer.npz` для использования при инференсе.

Модуль: `data_processing/kinematics.py`, класс `FeatureNormalizer`.

## 7. Конфигурация проекта

Все настраиваемые параметры системы вынесены в единый файл `config.py` с подробными комментариями. Файл организован в следующие разделы:

1. **Пути к данным** — директории для исходных, обработанных данных, моделей, логов
2. **Параметры устройства** — автоматический выбор GPU/CPU, random seed
3. **Параметры предобработки** — частота ресемплирования, порог GPS-аномалий, координаты ENU-начала
4. **Кинематические признаки** — количество признаков, размер окна сглаживания
5. **База целей** — количество целей и типов, размерности эмбеддингов
6. **Генерация данных** — количества траекторий по типам, диапазоны скоростей/высот/расстояний
7. **Архитектура TATPN** — параметры Multi-Scale CNN, Mamba, Cross-Attention, GRU Decoder
8. **Обучение** — batch size, learning rate, scheduler, early stopping
9. **Функция потерь** — веса multi-task loss (trajectory, target, ETA)
